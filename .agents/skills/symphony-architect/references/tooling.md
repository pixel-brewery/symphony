# Tooling, documentation and portable skills

Use for Nx/workspace changes, packaging, public contracts, generated output, documentation, skills, MCP and assistant configuration.

- Resolve projects/targets through [nx-workspace](../../nx-workspace/SKILL.md) and `yarn nx show project <name> --json`; run configured tasks through [nx-run-tasks](../../nx-run-tasks/SKILL.md). Use [nx-generate](../../nx-generate/SKILL.md) before app/library/project scaffolding and the package manager's workspace workflow for dependency linking. Do not guess flags or patch dependency resolution with ad hoc aliases.
- Inspect the actual source, entrypoints, manifests, build and consumers before changing package exports or adapter dependencies. Preserve the preload CommonJS exception and strict ESM application boundaries. A package being installed does not prove runtime registration or compatibility.
- Apply [symphony-docs](../../symphony-docs/SKILL.md) and [symphony-technical-docs](../../symphony-technical-docs/SKILL.md) for every implementation task. Update affected functional documentation under `docs/project`, feature-oriented technical documentation under `docs/architecture`, existing specification/operator/roadmap owners and `docs/adr/README.md` for material decisions. Keep public TSDoc, configuration examples, lifecycle/migration behavior and consumer prerequisites consistent with verified source. Do not invent a TypeDoc/OpenAPI pipeline absent from executable configuration.
- `.agents/skills` is the editable skill source. `AGENTS.md`, `.github/agents`, `.github/instructions`, `.github/prompts`, `.github/rules` and `.vscode/mcp.json` retain their established instruction/agent/MCP ownership. Keep provider adapters thin; do not create another authoritative instruction tree.
- Apply [manage-portable-skills](../../manage-portable-skills/SKILL.md) and [portable-skills instructions](../../../../.github/instructions/portable-skills.instructions.md): aligned name/directory, `name`/`description` frontmatter only, quoted `agents/openai.yaml` metadata with the literal invocation, required resources only and no secrets or absolute developer paths.
- Run `yarn agents:sync` after source changes and wait for completion before `yarn agents:check`. The generator owns provider adapters/mirrors, `.agents/packages` archives, `skills-lock.json`, `.codex`, `.opencode`, `.claude/skills`, `.claude/agents`, `.mcp.json` and `opencode.json`; never patch them by hand. Run Nx AI configuration before agent synchronization when both are needed.
- Keep the 13 `references/common` files and the `architect-core` entrypoint block identical to the peer architects. They are excluded from source formatting so formatting cannot rewrite retained upstream bytes. Put Symphony changes in local references. `architect-desktop-platform` is a compatibility entrypoint into this skill, not a second rule set.
- The local `.agents/scripts/sync_architect_core.py` recognizes Symphony and Synapse alongside the original peers. `--check` compares only common modules and the shared entrypoint block; project-specific helper scripts remain local. `--write` changes the explicitly selected peer's shared content and requires actual authorization; ordinary skill use needs no peer checkout.
- Regenerate design projections through `yarn design:md` after theme/icon/style/Mosaik input changes. Generated design previews follow `.design-sync/NOTES.md`. Keep authored documents distinct from generated output and verify affected links/packaging/discovery through their actual owner.
- Skill-only changes require meaningful source/link/core-equality/synchronization checks. They do not by themselves establish a product runtime, browser, package or release result. Broaden verification when the changed owner or repository-required gate calls for it.
