# Architecture application

Use with common Architecture and OOP/design patterns. Read the affected [desktop boundaries](../../../../.github/instructions/desktop-boundaries.instructions.md), [orchestrator architecture](../../../../.github/instructions/orchestrator-architecture.instructions.md) and [workspace structure](../../../../.github/rules/workspace-structure.md), then verify the current source paths.

- `apps/desktop` owns Electron lifecycle, windows/OS integration, credential mediation, validated IPC routing and Utility Process supervision. It does not own orchestration, Git, provider or persistence policy.
- `apps/renderer` is the sandboxed Angular composition root. `libs/frontend/core`, `libs/frontend/presentation`, feature libraries and shared UI own their existing client, presenter, routing and component seams. Renderer code has no Node.js, credential, filesystem, database or shell access.
- `apps/orchestrator` composes application use cases and adapters in the Utility Process. Domain, application, configuration, IPC and persistence have their own `core`, populated `features`, and required `composition` owners. Providers are grouped by their actual integration families. Skills and Workflow policy live in their Domain/Application features; execution-context composition lives in Application Execution, with filesystem access in its provider. The complete inventory and dependency matrix live in [dependency model](../../../../docs/architecture/dependency-model.md).
- The typed desktop boundary lives in `libs/ipc-contracts`: `@symphony/ipc-contracts-<feature>` owns method schemas, `@symphony/ipc-contracts-composition` combines the existing orchestration contract, and `@symphony/ipc-contracts-desktop` owns native methods. Validate requests, responses and events through these same Zod objects; do not restore the retired aggregate package or create a parallel contracts tree.
- Keep dependencies directed inward: renderer → typed contracts/domain, desktop → typed contracts, orchestrator → application/adapters, adapters → application contracts/domain, application → domain/execution context. Domain remains framework- and provider-neutral. Check actual Nx tags, imports, manifests and ESLint enforcement rather than relying on historical diagrams.
- Model state with immutable typed IDs, discriminated unions, exhaustive transitions, explicit errors and versioned configuration. Define leases, concurrent writes, restart/reconciliation, cancellation, disposal and recoverability at the actual owner before extending a cross-cutting capability.
- Executable target work uses isolated managed worktrees. Analyzer source access stays read-only. Preserve the explicit authorization and admission paths for provider execution, verification and delivery; UI visibility is not permission.
- No general internal HTTP server, NestJS, Express, additional UI framework or cloud runtime. The local mobile companion is only the [ADR-006](../../../../docs/adr/README.md) exception: `apps/mobile` assets, `libs/mobile-contracts`, a dedicated versioned contract, one selected private local-network interface and Utility Process supervision with pairing, authorization and limits.
- Keep secrets out of renderer state, public errors, logs and ordinary persisted records. Where credentials are persisted, retain the existing OS-backed encrypted/opaque-reference mediation rather than inventing a plaintext store.
- Record material decisions and migration/operational/verification consequences in the existing [architecture documents](../../../../docs/architecture/system-overview.md) or [ADR index](../../../../docs/adr/README.md). Do not turn an ordinary change into an unsolicited architecture report.
