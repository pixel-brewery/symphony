# Test integration

Use with common Testing and every affected production domain. Read [testing standards](../../../../.github/instructions/testing-standards.instructions.md) and the resolved Nx runner/configuration.

- Name the observable decision, invariant, contract, side effect, recovery or proven regression before adding a test. Choose the lowest reliable layer; duplicate coverage only for a distinct failure mode. No tests merely for static copy, icons, CSS, variants, trivial forwarding or a changed line.
- Every non-E2E unit/integration/IPC/contract/component/regression spec is adjacent to its exact source with matching casing: `ProductionFile.ts` owns `ProductionFile.spec.ts`. Split unrelated owners; do not add empty production files, aggregate scenario suites or separate test folders to manufacture ownership. Repository-policy specs and E2E journeys may remain behavior-named.
- Use the effective configured Vitest/Angular runner, typed fixtures, AAA-marked Arrange/Act/Assert, deterministic clocks/randomness and focused assertions. Restore spies/timers/global state and dispose owned resources. Do not add Jest or assume a neighboring project's coverage threshold.
- Domain tests remain infrastructure-free. Adapter integration uses isolated test-owned temporary SQLite files/directories/workspaces and deterministic cleanup, as required by Symphony's testing contract. Common shared-PostgreSQL/main-database examples do not override this local SQLite isolation policy. Never point fixtures at user application data or live customer/workspace credentials.
- Exercise meaningful Zod request and response validation at IPC/process boundaries. Verify invalid/unknown input, safe errors, authorization denials with no side effects, correlation, cancellation, bounds, provider failures and persistence recovery where those contracts change.
- Preserve genuine transaction/concurrency behavior for the boundary under test. A mocked repository/CLI/dispatcher proves only the layer above it; it cannot establish real persistence, transport isolation or native-process cleanup.
- Discover actual targets with `yarn nx show project <name> --json`. Run focused tasks through Yarn/Nx and broaden for evidenced risk or a required gate. Keep generation/integration prerequisites ordered; do not run competing heavy checks against shared outputs.
- Real-process isolation and renderer absence of Node.js access require [Electron E2E](e2e.md). A source test, screenshot or simulated adapter alone does not prove that boundary. Report the project, mode, checks and material limits of evidence.
