# Application, orchestration and persistence integration

Use with common Backend, Backend safety and the affected tests. Read [orchestrator architecture](../../../../.github/instructions/orchestrator-architecture.instructions.md), [persistence](../../../../docs/architecture/persistence-model.md) and the actual application/provider owner.

- Translate the common layering principles to Symphony: process dispatchers validate and delegate, application services own use cases/policy, ports isolate effects, and provider/persistence adapters own infrastructure. No Nest modules, decorators, Prisma repositories or HTTP controller framework are introduced through this guide.
- Reuse the existing application service and constructor-injected collaborators. Keep domain results and typed errors independent of Electron, GitHub, Codex, SQLite and operating-system types. Map external values and failures at their owning adapter and process-contract boundary.
- Persist through the established repository ports and SQLite adapters. The common `execute(query)` example describes data-access ownership; it does not authorize replacing existing Symphony repositories or adding Archipel. Preserve transaction/revision behavior, indexes, bounded reads and compatible migrations.
- Persist executions, attempts, events, selected skill versions, instruction hashes, locks, workspaces and recovery/audit evidence through the existing owners. Define unknown/newer-version behavior explicitly and preserve recoverable state on migration or partial failure.
- Commands carry a validated executable, arguments, working root, environment allowlist, timeout/output bounds and cancellation. Compose typed execution context; never concatenate arbitrary issue, model or repository text into shell commands.
- Preserve workspace/account/resource isolation and operation admission before side effects. Read/list/preview/download operations do not silently repair or delete state. Cleanup is an explicit scoped command with the existing active-owner protections.
- A workflow advertised as AI executes its configured AI runtime. Keep simulations explicit and test-only, classify failures honestly, and do not replay an implementation or other effectful attempt merely because another provider is available.
- Integrations publish consequences through the existing authoritative state/event owners. Define durability, deduplication and recovery when loss would break a contract; do not introduce a generic outbox, queue or health service without an actual owning need.
- Verify the changed application decision and the distinct persistence/provider/process seam. A mock of a lower boundary does not establish its real transaction, validation or recovery behavior. Update [execution lifecycle](../../../../docs/architecture/execution-lifecycle.md), [workspaces](../../../../docs/architecture/workspace-model.md) or another owning document when its contract changes.
