# Desktop and mobile transport contracts

Use with common Backend contracts and API URLs. Read [desktop boundaries](../../../../.github/instructions/desktop-boundaries.instructions.md), [IPC model](../../../../docs/architecture/ipc-model.md), the actual `libs/ipc-contracts` schema and its consumer before changing a method.

- The desktop transport is the narrow typed preload API, not an HTTP API. Keep method-specific Zod request/response/event contracts, correlation IDs and safe discriminated errors. Reuse the existing method union, fixed channels, preload API, Main routing and Utility Process dispatcher.
- Validate unknown input at every real trust boundary and validate returned values before renderer use. Check preload, Main and Utility Process behavior together. Do not expose arbitrary channels, `ipcRenderer`, generic shell/filesystem handles, raw provider payloads or credentials.
- Derive transport types from the canonical schema where that owner uses inference. Keep constraints, defaults, bounds, transforms and input/output meaning explicit; preserve the public one-export/file convention and existing cohesive schema/type exceptions described by the instruction checker. Do not hand-maintain another wire model.
- Common Nest pipes, `@SerializeOptions`, `ResponseReturn2`, mapping services, Swagger projection and generated HTTP clients are examples of one owned contract, not installed Symphony transport requirements. Do not wrap IPC in HTTP envelopes or add OpenAPI generation to satisfy them.
- Trace each changed method through application/domain mapping and the real renderer client. Preserve method identifiers, authorization, sender/origin checks, correlation, timeout/cancellation semantics, event subscriptions and secret-safe error projection. Never treat a long-running admitted execution as an ordinary short IPC request.
- Operating-system capabilities terminating in Main retain their existing separate typed desktop contract. Credential mediation uses the narrow existing named flow; a required secret-bearing login payload is handled only at that boundary and is never echoed into renderer state or diagnostics.
- The local companion uses `libs/mobile-contracts` and the [mobile contract](../../../../docs/architecture/mobile-companion-phase-1.md). Apply common HTTP URL/status/media rules only to actual HTTP routes. Preserve versioning, pairing, authorization, selected private interface, payload/rate/resource limits and lifecycle; desktop IPC does not become REST.
- Prove meaningful valid/invalid input, transformed/serialized output, unknown methods, correlation/error behavior and actual consumer compatibility. Run source-owner contract tests and relevant real-process journeys; a schema-only test cannot prove the complete process path.
