# Skill resolution

Portable skills are discovered from three explicit roots:

1. Symphony-owned user skills in `<configuration root>/skills`. This is the only writable catalog root and prevents normal application startup or catalog hydration from enumerating a user's global agent configuration. An operator may still import one explicitly selected portable skill folder through the native file dialog.
2. Repository skills in `<active source>/.agents/skills`. These are discovered from the configured current source and remain read-only because Symphony never mutates a user's ordinary checkout.
3. An optional legacy root supplied explicitly to the Utility Process. Packaged Symphony defaults this to an empty application-owned directory and never scans `~/.codex/skills` implicitly.

Every discovered directory must contain a valid `SKILL.md`. Catalog entries expose provenance, location, content digest, modification time, invocation policy and resource count. The package ID combines provenance and the standardized skill name, so identical names from different roots remain visible and auditable. A repository or legacy package can be copied into the shared root, after which it is independently editable and updateable.

Discovery does not grant execution permission. When activating an exact package ID from the Skills catalog drawer, the user must assign it to one explicit AI flow role: Issue drafting before the workflow, Analysis and re-analysis, Implementation and revision, CI diagnosis, CI repair, or pull-request review. Application settings persist the activation and the one-to-one role assignment. Assigning another package to an occupied role deactivates the previous package instead of introducing ambiguous precedence. Activation makes the associated capability available but never enables agentic-delivery policy, selects an AI mode, or disables the manual path. Analyzer, Solver, Issue drafting, and Agentic Delivery resolve only the exact assigned active package; names and descriptions no longer route production execution. An AI action is rejected before provider work when its required role is unassigned or unavailable. Existing settings without assignments receive a one-time name-based migration for the three formerly implicit roles. Production executions record the exact package ID, digest, and minimal instructions snapshot required for restart recovery.

The action and orchestrator choose the phase; a skill never infers or declares it. The task drawer remains structurally stable and defaults every AI-capable step to `Manual`. Selecting `With AI` for Analyze or Re-analyze resolves the workspace-owned analysis role, accepts an optional focus request, and causes Symphony to own the provider-neutral `ready` transition before the bound agent starts. Selecting it for Implement or Rework resolves the solution role and causes Symphony to own the `executing` transition; AI rework requires a new request. Selecting it for Board creation reveals the Prompt Box and work-item-creation role but does not introduce an execution phase: Symphony runs the exact workspace-owned creator package read-only and supplies the current provider-neutral repository, label, assignee, state, and field options as a closed classification allowlist. Only a complete validated result is applied to the unsaved review form. The user's later `Create work item` or `Save changes` action owns the tracker mutation. Manual branches accept the same provider fields or Markdown outcomes without invoking skills. Skill instructions govern how work inside an opted-in AI action is performed, while Symphony governs when it runs, its sandbox, tracker mutations, workspace policy, persistence, and terminal state.

The renderer reflects the same resolution contract instead of guessing from skill names. Manual is always the initial segment and uses the primary presentation. `With AI` is a separate highlighted segment; an assigned role names the selected package, while an unassigned role disables only that AI execution and offers the Skills drawer as the corrective action. AI-originated results display the package recorded on their immutable execution; manual results are labeled as manually recorded.

No locally inspected FLAMOX365 skill body is copied. Existing skills inform responsibility boundaries and can be imported intact through the standard package architecture.

Symphony's repository-local assistant skills live at `.agents/skills` and are therefore discovered when this repository is the active source. Generated wrapper skills make scoped repository agents, instructions, prompts, and rules discoverable without duplicating their bodies. See [repository AI configuration](repository-ai-configuration.md) for source ownership and synchronization.
