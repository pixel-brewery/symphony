# Mosaik integration

Mosaik 0.1.199 is installed from GitHub Packages under the `@pixel-brewery` scope. Angular uses `@pixel-brewery/mosaik-elements-angular` standalone wrappers; the foundation, element, icon, theme, Markdown, and peer packages are installed explicitly. `provideTheme` initializes `SohoTheme.SOHO_THEME` with the reference's light-mode fallback, complete semantic light/dark palettes, typography, layout, and schemes. The composition root also applies the compatible private upstream application Mosaik defaults for input components, toasts, animations, drawers, dialogs, sheets, forms, message boxes, and time updates. Mosaik Foundation supplies its minimal non-overwriting Reicon fallback automatically; Symphony's desktop and mobile registries use named Reicon definitions from `@pixel-brewery/mosaik-icons/reicon` for application glyphs and named package definitions from `devicon`, `simple-icons`, or `svgl` only for provider marks. `provideIcons` registers those definitions while templates and mobile navigation descriptors pass stable registered names through the public `icon` input. No raw SVG path data remains in the productive application registries. Constant menu modes use static `menu-mode` attributes so portal projection is initialized before custom-element connection. The root document seeds `theme="soho"` before wrapper registration so shadow styles finalize deterministically.

Global SCSS includes `@pixel-brewery/mosaik-themes/scss`, `soho-style()`, and the existing shell geometry overrides. The private upstream application-only feedback overlay rules are intentionally excluded because they target product-owned overlay classes rather than Mosaik elements. The renderer also carries the complete reference Tailwind v4 utility layer and Soho bridge. Product-specific layout uses Mosaik design tokens and custom properties instead of replacing controls. The main window uses `mosaik-app` without its header and navigation (`provideAppComponent({ hasHeader: false, hasNav: false })`) and composes the sidebar, unified toolbar and status bar from plain `part`-named regions whose surfaces, hairlines and compact control density come from Mosaik tokens and public component custom properties in `overrides/window-chrome.scss` ([Window chrome and navigation](window-and-navigation/README.md#gestaltungsvertrag)); path selection uses Mosaik FileBox controls with native desktop dialogs; actions use Mosaik buttons and badges; the board uses the actual Mosaik FlowBoard family.

The theme package retains a narrow [consumer patch for Windows path separators](application-updates/packaging.md#cross-platform-consumer-build-contract) in the design-document generator. Foundation retains a [controlled FlowBoard drag patch](board/README.md#einträge-stapel-und-virtualisierung) that keeps Angular-owned card nodes in their source column until the model changes. The local design catalog is pinned to the same Mosaik release. Actions uses ngPEL 0.0.8 to supply the context-menu interaction around Mosaik Popup and Menu.

The package currently triggers an Angular optimization warning because one Mosaik transitive path uses `reflect-metadata` CommonJS. This is a build-performance warning, not a renderer security exception. The bootstrap E2E test verifies that a Mosaik app shadow root exists and that its themed rail constrains layout.

The 0.1.154 upgrade and Memphis preset produce a 15.16 MB initial mobile bundle.
The mobile production budget allows 16 MB before warning and fails at 18 MB,
while retaining the existing 4 KB/8 KB component-style limits. This accommodates
the current upstream dependency size without disabling the size gate.

Symphony selects the Soho preset across desktop, menu bar, Mobile and design previews. Empty application theme overrides preserve the preset. Tailwind follows Soho’s 8 px rhythm and 10 px radius, and Inter is packaged locally. The shell overrides carry geometry and token-only chrome surfaces — the window chrome sheet paints the sidebar and status bar with `--mosaik-color-neutral-100` and separates regions with `--mosaik-scheme-highlight` hairlines — and the `technical-value` sheet remains active; the remaining legacy styling stays disabled. The design-document CLI accepts the published Soho model directly.

Delivery-process and CI-job diagrams use the optional `components/flow` entry points of the Angular and Foundation packages. Mosaik owns nodes, orthogonal connections, selection, viewport gestures and measured Dagre layout. The layout library loads on demand. The delivery process supplies Mosaik viewport controls and a minimap through optional slots. The compact CI-job diagram leaves those slots empty and uses the same native gesture and keyboard navigation. Symphony projects provider-neutral records and executions and supplies no graph-specific styles. The former Foblex packages, manual CI layout and global Foblex stylesheet are removed.
