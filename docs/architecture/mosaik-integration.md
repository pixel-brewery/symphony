# Mosaik integration

Mosaik 0.1.173 is installed from GitHub Packages under the `@pixel-brewery` scope. Angular uses `@pixel-brewery/mosaik-elements-angular` standalone wrappers; the foundation, element, icon, theme, Markdown, and peer packages are installed explicitly. `provideTheme` initializes `SohoTheme.SOHO_THEME` with the reference's light-mode fallback, complete semantic light/dark palettes, typography, layout, and schemes. The composition root also applies the compatible FLAMOX365 Mosaik defaults for input components, toasts, animations, drawers, dialogs, sheets, forms, message boxes, and time updates. Mosaik Foundation supplies its minimal non-overwriting Reicon fallback automatically; Symphony's desktop and mobile registries use named Reicon definitions from `@pixel-brewery/mosaik-icons/reicon` for application glyphs and named package definitions from `devicon`, `simple-icons`, or `svgl` only for provider marks. `provideIcons` registers those definitions while templates and mobile navigation descriptors pass stable registered names through the public `icon` input. No raw SVG path data remains in the productive application registries. Constant menu modes use static `menu-mode` attributes so portal projection is initialized before custom-element connection. The root document seeds `theme="soho"` before wrapper registration so shadow styles finalize deterministically.

Global SCSS includes `@pixel-brewery/mosaik-themes/scss`, `soho-style()`, and the existing shell geometry overrides. The FLAMOX365-only feedback overlay rules are intentionally excluded because they target product-owned overlay classes rather than Mosaik elements. The renderer also carries the complete reference Tailwind v4 utility layer and Soho bridge. Product-specific layout uses Mosaik design tokens and custom properties instead of replacing controls. The shell uses `mosaik-app`/`mosaik-app-header`; path selection uses Mosaik FileBox controls with native desktop dialogs; actions use Mosaik buttons and badges; the board uses the actual Mosaik FlowBoard family.

Symphony carries no Yarn patches for Mosaik. A Mosaik defect is fixed in the Mosaik repository and reaches Symphony through a published release; since 0.1.157 the foundation's comment themes let long content shrink (`min-width: 0`), and the `mosaik-design-md` bin of the themes package accepts the Soho base theme.

The package currently triggers an Angular optimization warning because one Mosaik transitive path uses `reflect-metadata` CommonJS. This is a build-performance warning, not a renderer security exception. The bootstrap E2E test verifies that a Mosaik app shadow root exists and that its themed rail constrains layout.

The 0.1.154 upgrade and Memphis preset produce a 15.16 MB initial mobile bundle.
The mobile production budget allows 16 MB before warning and fails at 18 MB,
while retaining the existing 4 KB/8 KB component-style limits. This accommodates
the current upstream dependency size without disabling the size gate.

Symphony selects the Soho preset across desktop, menu bar, Mobile and design previews. Empty application theme overrides preserve the preset. Tailwind follows Soho’s 8 px rhythm and 10 px radius, and Inter is packaged locally. The shell overrides carry geometry only — the title bar takes Soho's flat `bg-background` header — and the `technical-value` sheet remains active; the remaining legacy styling stays disabled. The design-document CLI accepts the published Soho model directly.

Delivery-process and CI-job diagrams use the optional `components/flow` entry points of the Angular and Foundation packages. Mosaik owns nodes, orthogonal connections, selection, viewport controls, minimaps, and measured Dagre layout; the layout library loads on demand. Symphony projects provider-neutral records and executions, retains the existing detail/log commands, and supplies no graph-specific styles. The former Foblex packages, manual CI layout and global Foblex stylesheet are removed.
