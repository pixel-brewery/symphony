# Platform extensions

The desktop platform introduces concepts beyond the Symphony draft: target projects, versioned workflow profiles, skill manifests and trust levels, instruction hashes, durable execution attempts, audit events, typed command policies, credential profiles, workspace leases, configured GitHub status mappings, and user-controlled automation policies.

These extensions exist to make a local operator product recoverable and explainable. They do not add target-project business logic. Every target repository remains independent and supplies only trusted instructions, quality profiles, and optional project skills through explicit resolution boundaries.

## Production orbit and employee landscape

Version-six settings add employee appearances and delivery targets without changing existing
IDs, custom workflows or execution snapshots. Orbit is the default desktop route; Board
and the previous Home URL remain valid. Orbit, Stages and Board share selection and filters.
Actual immutable execution bindings own employee activity, while goal responsibility applies
to subsequent phases. The visual setup saves only on Apply and can run the shipped read-only
analysis role without an imported skill package or a deployment configuration.

GitHub is the first evidence and deployment adapter. Publication, installation and deployment
are distinct evidence kinds; ticket inclusion requires a recorded pull-request relationship
and proven revision ancestry. Commands use the existing typed desktop boundary. Definition
and job graphs are read at the actual run revision. See [production orbit architecture](../architecture/production-orbit.md)
for workflow inputs, channel pointers, installation receipts and unknown-response handling.
