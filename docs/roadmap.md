# Roadmap

## Current platform baseline

- Angular/Mosaik Memphis desktop and Mobile, with Production Orbit, Stages, employee figures, visual project setup, Board, the retained Home overview, Actions, Skills and expert Settings.
- Shared scene/filter/selection projections, deterministic grouped positions and a lazy Three.js spatial projection with the same accessible PNG controls.
- Version-six configuration, stable employee appearances, actual execution activity and next-phase assignments without replacing running CLI processes.
- GitHub delivery evidence, explicit release channels, installation receipts, revision-bound Actions graphs, declared dispatch inputs and revalidated environment reviews. External write intents persist before submission and unknown outcomes remain blocked until attributable evidence is available.
- Typed Zod IPC through sandboxed preload to a supervised Utility Process.
- Strict Workspace Definitions with aggregate Workspace Views and color plus short-code identification.
- Azure DevOps Work Items through WIQL/saved queries, GitHub Cloud source bindings, and GitHub Actions visibility/control.
- Multiple workspace-owned Codex/ChatGPT and Claude profiles with immutable execution binding snapshots.
- Per-workspace SQLite execution state, account runtime homes, and Git worktree roots.
- Workspace-owned AI positions, agents, teams, account/model routes, adaptive failover, route circuits, account quota cooldowns, and model lockout.
- Delegated ticket goals with responsible-versus-executing employees, immutable implementation contracts, same-worktree handoffs, scope/diff enforcement, deterministic repository checks, bounded revisions, and explicit evidence-based approval.
- Workspace provider capability manifests, fail-closed free-tier terms evidence, nine explainable route strategies, provider-level circuits, OpenCode multi-provider discovery, and optional OpenAI-compatible workspace gateways.
- Read-only Analyzer worktrees; writable Solver/revision worktrees without automatic commit, push, merge, or default-branch mutation.
- Disabled-by-default remote GitHub automation with authorized Issue/Project synchronization, `@symphony` commands, durable deduplication, and GitHub Actions reruns while the renderer is closed.
- Disabled-by-default autonomous workflow cycles with a configurable 15-minute default interval, fair Backlog/Ready/retry scheduling, a global three-execution default capacity, automatic managed-branch pull-request delivery, and pull-request-driven Review/Completed transitions.
- Restricted-by-default managed Git clone/fetch, machine-local capability grants, manifest-based Node.js/.NET/Python/Java/Go/Rust verification plans, and cancellable credential-free host execution in commit-pinned worktrees.
- Disabled-by-default managed local GitHub Actions execution in one disposable mount-free Linux VM, with bounded resource presets, workspace-owned runtime storage, run-scoped self-hosted-runner labels, pinned runtime assets, normal GitHub check reporting, audit evidence, supervised teardown, and startup reconciliation.

## Next hardening increments

- Interactive Microsoft Entra/Azure DevOps sign-in when a deployable Symphony OAuth client exists; OS-secured PAT entry is the current desktop flow and environment references remain available for unattended bootstrap.
- Azure DevOps work-item type/field discovery and rich HTML/Markdown editing beyond the current common fields.
- Managed Git clone/fetch leases, disk quotas, offline cache, and broader repository discovery.
- Container/VM enforcement for untrusted project filesystem and network isolation, plus supervised multi-service E2E readiness and structured artifact collection.
- Delivery change inspection with structured diff/commit history and approval-controlled commit/push/pull-request handoff.
- Saved aggregate views, grouped board layout, and provider-error isolation per workspace so one unavailable customer account does not hide healthy workspaces.
- Additional adapters (for example Azure Pipelines or GitLab) only behind the existing capability-specific ports.
